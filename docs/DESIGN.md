# Personal Reading OS 设计与信息架构

## 1. 视觉定位与原则

视觉方向是“Apple Books 的阅读舒适感 + Notion 的知识管理简洁感”。只借鉴阅读体验与信息组织理念，不复制具体产品界面。关键词：**安静、温暖、纸张感、克制、大量留白、内容优先、适合长时间阅读**。

- 书籍、摘录和用户写下的文字是视觉中心；导航与操作始终为内容服务。
- 优先通过留白、排版、书籍封面和轻量分割建立层次，减少容器嵌套。
- 避免典型 SaaS 后台布局、大量卡片或边框、高饱和颜色、蓝紫渐变、发光效果、过度科技感、滥用圆角与复杂动画。
- 界面在长时间使用时应稳定、低干扰；状态区分不能只依赖颜色。
- 所有主要交互都要兼顾键盘、触控和可访问性。

## 2. 颜色系统

V0.1 采用暖色浅色主题。以下颜色作为语义色使用，页面中不随意增加大量新颜色。强调色主要用于选中状态、主要操作和阅读状态。

| 语义 | 色值 | 主要用途 |
| --- | --- | --- |
| 页面背景 | `#F7F6F2` | App Shell、页面底色 |
| 主要内容背景 | `#FCFBF8` | 阅读和编辑内容表面、必要的浅色区块 |
| 主要文字 | `#252522` | 标题、正文、关键操作文字 |
| 次级文字 | `#73716B` | 作者、日期、来源、说明 |
| 弱化文字 | `#A3A098` | 低优先级提示和装饰性信息；重要内容不要仅用此色 |
| 分割线 | `#E8E5DE` | 轻量内容分隔、输入框边界 |
| 主要强调色 | `#667A68` | 当前导航、主操作、阅读状态 |
| 浅强调背景 | `#E9EEE8` | 选中项背景、轻量状态提示 |

同类状态优先通过文字、图标或位置表达，颜色只做补充。悬停、按下和焦点状态应从这套语义色推导，并检查文字与背景对比度。未来支持 Dark Mode；V0.1 仅建立便于换主题的语义命名和结构，**不实现完整深色主题或切换功能**。

## 3. 排版与空间

- 普通 UI 与正文优先使用清晰的系统字体栈，不为视觉风格引入额外字体依赖。
- 标题、正文、辅助信息建立稳定层级：页面标题明确，正文易读，元信息安静。通过字号、间距和文字颜色形成层级，避免堆叠粗体。
- 阅读器正文与普通 UI 明显区分：更适合连续阅读的字号、行高和段落节奏；具体值在阅读器阶段结合真实 EPUB/PDF 内容验证。
- Desktop 阅读器正文居中，建议最大宽度约 **680–760px**，不要铺满屏幕；普通内容页也要控制可读行长。
- Dashboard 可使用更宽的内容区域；不要把阅读器正文的宽度上限套用到 Dashboard。
- 间距使用一致的节奏，例如 4/8/12/16/24/32/48px，优先拉开章节与内容组的距离，而非增加边框。
- 长书名、摘录、标签与随笔正文要允许换行；空状态和短内容也应保持舒服的页面呼吸感。

## 4. 页面结构

| 路由 | 页面 | 主要内容与入口 |
| --- | --- | --- |
| `/` | Dashboard | 问候/日期、继续阅读、最近阅读、最近笔记/灵感、少量统计、快速记录 |
| `/library` | 我的书架 | V0.2 展示用户手动添加的书籍、阅读状态与人工页码进度；V0.3 再提供文件导入。 |
| `/library/new` | 添加书籍 | V0.2 录入书名、作者、阅读状态、总页数和当前页数。 |
| `/library/[bookId]` | 书籍详情 | V0.2 展示书籍信息与进度，并提供阅读状态和当前页数更新。 |
| `/reader/[bookId]` | 阅读器 | 后续承载 EPUB/PDF 正文、章节/页码、进度、设置、高亮与笔记 |
| `/notes` | 阅读笔记 | 笔记、来源与标签信息；后续提供编辑和跳回原文 |
| `/reflections` | 阅读心得 | 整书/章节心得列表；后续提供编辑 |
| `/ideas` | 灵感 | 易扫描的想法列表；后续提供快速记录与整理 |
| `/writing` | 随笔 | 长文本列表；后续提供编辑与引用 |
| `/search` | 全局搜索 | 后续提供跨内容查询、结果分组与来源跳转 |
| `/settings` | 设置 | 阅读偏好、外观、账户与标签管理入口，按阶段逐步开放 |

V0.1 建立计划路由的页面骨架和可信的空状态。静态示意内容须清楚标注，不能让导入、搜索、保存或阅读功能看起来已经可用。具体交互按 [ROADMAP.md](./ROADMAP.md) 逐阶段增加。

## 5. 导航与响应式布局

| 视口 | 布局 | 导航行为 |
| --- | --- | --- |
| Desktop `≥1100px` | 固定、稳定的左侧 Sidebar + 主内容区域 | Sidebar 常驻；主要内容保持合适行宽。 |
| Tablet `768–1099px` | 顶部导航 + 可打开的导航抽屉 + 主内容区域 | 导航抽屉可关闭，优先让出阅读和写作空间。 |
| Mobile `<768px` | 简化顶部栏 + 底部主要导航 | 不显示 Desktop Sidebar；底部导航避开系统安全区域。 |

- Desktop Sidebar 可包含首页、书架、笔记、心得、灵感、随笔、搜索；设置作为次级入口。当前页面有明确选中状态。
- Mobile 底部导航优先为：**首页、书架、快速记录 `+`、笔记、我的**。“我的/更多”通向设置及灵感、随笔、搜索等次级入口；不因此新增独立的 `/me` 路由。
- 阅读器采用更沉浸的独立页面布局，进入后弱化或隐藏应用主导航，并提供清楚的返回路径。
- 标签属于跨内容组织能力，通过内容筛选和设置中的管理入口访问，暂不单独增加必需的顶级路由。
- 每个页面从开发第一天同时考虑 Desktop、Tablet、Mobile，不能只完成 Desktop 再忽略 Mobile。避免横向滚动；弹层、软键盘、屏幕旋转与触控安全区域都要纳入检查。
- 断点是起始规则，最终以真实设备上的内容和操作体验验证。

## 6. 重点页面的视觉规则

### Dashboard

首页应像阅读空间，而不是数据后台。视觉顺序优先为：问候/日期 → 继续阅读 → 最近阅读 → 最近笔记 → 最近灵感 → 快速记录 → 少量阅读统计。根据实际内容可以调整排布，但“继续阅读”始终容易找到。

不要把每一区域都放进独立卡片。用留白、字体层级、细分割线、书籍封面和必要的轻量背景组织内容。统计只作简短摘要，不使用密集图表抢占首屏。V0.2 接入数据后，“继续阅读”和基础书籍数量必须来自当前用户的真实数据；尚未实现的笔记、灵感、阅读时长和复杂统计使用真实空状态或暂不展示，不继续显示虚构成绩。

### 我的书架

书籍封面是主要视觉元素，书名和作者紧随其后，再展示阅读状态与进度。操作入口应清楚但不覆盖大面积封面。布局为未来 Grid/List 切换留出空间；V0.2 使用文字与既有色彩生成轻量封面占位，不增加真实封面上传。空书架提供“添加第一本书”入口，有数据时提供稳定可见的“添加书籍”操作。

### 添加书籍

`/library/new` 使用独立页面承载基础表单，避免在 Mobile 上把主要流程塞入狭窄弹层。字段包括书名、作者、阅读状态、总页数和当前页数；书名与总页数为必要信息，作者允许为空。当前页必须在 0 与总页数之间。

- 使用明确的 `label`、说明与字段级错误，不只用 placeholder 表达含义。
- 保存期间禁用重复提交，并保留清楚的提交状态；失败时保留用户已经输入的内容。
- 保存成功后进入新书的详情页；取消或返回应回到书架，不创建记录。
- Desktop 表单控制可读宽度；Tablet 与 Mobile 使用单列布局，输入框和按钮满足触控尺寸。

### 书籍详情与人工阅读进度

`/library/[bookId]` 展示书名、作者、阅读状态、当前页/总页数、百分比和进度条。页面仍属于普通 App Shell，不采用未来 Reader 的沉浸布局。

- 用户可以修改阅读状态和当前页数；百分比由当前页与总页数自动计算，不提供单独的百分比输入。
- 更新成功后，详情页、书架和 Dashboard 应读取同一份最新数据；失败时明确说明且不显示虚假成功状态。
- 不存在或不属于当前用户的书籍使用一致的 Not Found 状态，不能泄露其他用户的书籍信息。
- `current_page` 是 V0.2 的人工记录入口，不代表 EPUB/PDF Reader 的真实内容位置；详情页不展示尚未可用的“打开阅读器”操作。

### 阅读器

阅读器比其他页面更沉浸：正文优先，章节和进度容易查看，阅读设置、高亮与笔记在需要时易于使用。Desktop 正文居中并限制宽度；工具栏在不使用时降低视觉存在感。EPUB 与 PDF 的阅读设置按各自格式能力设计，不强行统一。阅读器业务功能分别在 V0.4、V0.5、V0.6、V0.7 实现；V0.1 只考虑其导航入口与页面布局边界。

### 笔记、心得与灵感

笔记页面强调文字本身，不将每条笔记做成厚重卡片。单条内容可按日期、来源书籍、摘录、用户笔记、标签的顺序呈现，用留白与细分割线区分。心得保持适合长文本的宽度和段落节奏。灵感列表便于快速扫描，短内容也不应被过多装饰包围。

## 7. 快速记录

快速记录是 Mobile 的核心路径，未来目标流程为：**打开应用 → 点击 `+` → 选择灵感/笔记/心得/随笔 → 输入 → 保存**。选择类型后尽量直接聚焦输入区，减少必填项；若从阅读器进入，应尽可能带上来源上下文。用户保存前需要清楚知道当前记录类型。

V0.1 仅建立 `+` 的导航位置和视觉样式，必要时展示“功能将在后续阶段开放”的明确状态。创建与保存逻辑属于 V0.8，不在 V0.1 假装完成。

## 8. 基础组件与交互语言

- **V0.1 基础件**：App Shell、Sidebar、Mobile 顶部栏/底部导航、主内容容器、页面标题、基础按钮、基础输入框、Typography、空状态。
- **后续内容件**：书籍封面/书籍行、内容摘要行、来源标识、状态标记、标签、加载/错误状态；根据对应功能阶段逐步实现。
- **后续阅读与编辑件**：目录、进度、阅读设置、高亮操作层、笔记/条目编辑区与引用展示；不在 V0.1 预建完整系统。
- 普通容器圆角建议 **8–12px**；重要浮层可略大，但不要让所有元素都圆角。
- 阴影只用于浮层、Modal、悬浮操作和必要的层级区分；普通内容区域尽量不用明显阴影。
- 动画保持克制，只辅助页面状态切换、Sidebar、Modal、Hover 与展开/收起；避免复杂入场动画，并尊重减少动态效果的系统偏好。
- 每个内容页面最终需要空、加载、错误和有数据状态；V0.1 先设计可信的空状态。保存、导入、删除等反馈在实际功能阶段实现。

组件只在真实复用时提取，优先保持职责清晰与可维护性。

## 9. V0.1 设计目标与边界

V0.1 只建立：**应用整体视觉语言、Sidebar、Mobile Navigation、响应式页面布局、Dashboard、基础页面空状态、基础按钮、基础输入框和基础 Typography**。阶段验收需在 Desktop、Tablet、Mobile 检查导航、行宽、留白、触控区域、键盘焦点及横向溢出。

V0.1 暂不实现阅读器业务功能、数据库、AI、复杂动画、完整 Dark Mode 或真实书籍上传。后续功能的页面入口应清楚标识当前状态，不承诺尚未提供的能力。

## 10. V0.2 视觉延续与范围

V0.2 在 V0.1 已建立的暖白背景、低饱和灰绿色、系统字体、大量留白、克制圆角和轻量分割基础上增加真实数据状态，不重做 App Shell 或整体视觉语言。

本阶段新增的书架列表、书籍表单、详情页与进度更新需要覆盖空、加载、错误和有数据状态，并同时验证 Desktop、Tablet、Mobile。V0.2 不通过增加大量卡片、阴影或颜色来表达“数据已接入”，也不提前设计 EPUB/PDF Reader、复杂统计或后续内容模块。
