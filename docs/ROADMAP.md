# Personal Reading OS 路线图

## 阶段原则

每次只开发一个阶段。阶段开始前阅读 [PRD.md](./PRD.md)、[DESIGN.md](./DESIGN.md)、[DATABASE.md](./DATABASE.md) 和本文件；阶段完成后检查相应页面的桌面/平板/手机表现，运行必要检查并记录遗留问题。阶段中的依赖与具体实现方案应在该阶段说明和确认。

| 阶段 | 目标与交付 | 完成判据 |
| --- | --- | --- |
| **V0.1 基础 UI** | 建立响应式 App Shell、导航、页面骨架、基础排版与空状态；九个计划路由可到达。 | 桌面、平板、手机布局可用；导航状态清楚；不暗示数据功能已上线。 |
| **V0.2 — Data Foundation & Bookshelf MVP** | 接入最小用户认证与 Supabase/PostgreSQL 数据基础，建立私有用户数据边界；支持手动添加书籍、Bookshelf、Book Detail、人工页码阅读进度，以及 Dashboard 真实数据联动。 | 登录/退出与受保护页面可用；用户只能访问自己的数据；可以完成“添加书籍 → 查看详情 → 更新页码 → Dashboard 显示最新进度”的闭环；凭据不在源码，RLS 策略可验证。 |
| **V0.3 — 文件导入与 Storage 基础** | 实现 EPUB/PDF 文件导入、私有对象存储、格式元数据、封面提取或管理、重复检测与导入失败反馈；在 V0.2 的书架数据基础上扩展。 | EPUB/PDF 导入后可在书架中查看和管理；失败、重复与不支持格式有清晰反馈；跨账户不能读取文件。 |
| **V0.4 EPUB 阅读器** | 实现 EPUB 正文、目录、排版设置与基础导航。 | 可打开书架中的 EPUB，并在桌面和触屏设备上稳定翻阅。 |
| **V0.5 PDF 阅读器** | 实现 PDF 页面阅读、页码导航、缩放与适配布局。 | 可打开书架中的 PDF，页面和导航在目标设备上可用。 |
| **V0.6 阅读位置与会话** | 保存/恢复 EPUB CFI、PDF 页码及适用的视图位置，记录可靠的阅读会话，并建立跨设备同步规则。 | 重新打开阅读器能恢复真实内容位置；跨设备冲突规则明确并可验证；阅读时长与后续统计有可信基础数据。 |
| **V0.7 笔记与高亮** | 实现 EPUB/PDF 摘录、高亮、阅读笔记和跳回原文。 | 笔记保留来源与可用位置；从笔记可返回原文；定位失败有说明。 |
| **V0.8 灵感/心得/随笔** | 实现三类 Entry、关联与引用、跨主要页面快速记录。 | 各类型可创建/编辑/查看；心得可关联书籍与笔记；随笔可引用已有内容。 |
| **V0.9 搜索/标签/统计** | 实现跨内容搜索、统一标签管理、Dashboard 摘要和阅读统计视图。 | 书籍、笔记/摘录及三类 Entry 可检索；标签筛选一致；统计有可追溯来源。 |
| **V1.0 PWA + 正式部署** | 完成安装体验、生产部署、质量与隐私检查、主要流程打磨。 | 目标设备完成主要流程；PWA 可添加到主屏幕；生产环境可用。离线能力范围需单独确定。 |
| **V2.0 AI** | 规划并逐项评估 AI 问书、个人笔记问答、笔记整理、跨书观点联系、写作助手、双向链接、知识图谱、语义搜索和年度 AI 阅读总结。 | 当前仅保留规划；在 V1.0 完成后再决定范围、数据授权、成本与优先级。 |

## 当前状态

**V0.1 基础 UI 与 V0.2 — Data Foundation & Bookshelf MVP 已完成。** V0.2 已交付 Supabase/PostgreSQL 数据基础、单用户 Email + Password 认证、受保护路由、RLS 私有数据边界、手动添加书籍、真实书架、书籍详情、人工页码与阅读状态更新，以及 Dashboard 真实数据联动。添加书籍和阅读状态保存分别使用数据库 RPC；页码与阅读状态在一次原子调用中更新。

当前主流程为：**登录 → Dashboard → 书架 → 添加书籍 → 书籍详情 → 更新阅读进度 → Dashboard 同步**。个人用户由 Supabase Dashboard 手动创建，应用不开放注册。

V0.2 不使用 Magic Link。后续如配置可靠的自定义 SMTP，可重新评估将 Magic Link 作为个人登录方式。

V0.2 的 `current_page` 只用于用户手动记录纸质书或页码明确内容的阅读进度。EPUB/PDF 文件导入继续保留在 V0.3；EPUB/PDF Reader、CFI/PDF 真实阅读位置、阅读会话与跨设备位置恢复继续由 V0.4–V0.6 负责，不在 V0.2 提前实现。

V0.3 — 文件导入与 Storage 基础尚未开始。Notes CRUD、Ideas、Reflections、Search 后端、阅读时长与 AI 仍属于后续阶段。
